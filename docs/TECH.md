# TECH — Pushups (working title)

Version 1.0 · 7 Nov 2026

## 1. Stack decision

**Kotlin Multiplatform (KMP) + Compose Multiplatform (CMP), Android target first, iOS added later.**

Why:
- **Android-native performance and APIs.** On Android, Compose Multiplatform *is* Jetpack Compose, so the
  app runs as a fully native Android app: widgets (Glance), Health Connect, haptics, shaders and
  120 Hz-ready animation are all first-class.
- **The iOS port is mostly free.** Logic, data and the custom-drawn UI live in shared code. Compose for iOS
  has been stable since CMP 1.8 (May 2025); current is 1.12 (Oct 2026). Because this app uses its
  *own* visual language rather than stock platform components, a shared UI renderer is an advantage.
- **Rich visuals are portable.** The glass and blur libraries we'll use (Kyant Backdrop, Haze) support
  Compose Multiplatform.
- **Escape hatch:** if a future iOS version should use native SwiftUI (e.g. for Apple's own Liquid Glass),
  the domain and data layers are already shared and UI-free. The wizard's `sharedLogic` / `sharedUI`
  split makes that a mechanical change.

Rejected: React Native/Expo (widgets and rich motion need native code anyway; less smooth for shader-heavy
UI), Flutter (Dart, widgets less native, no reuse of Android APIs), native-Android-only (blocks the iOS port).

## 2. Project structure

Use the **current default KMP structure** generated by the wizard (kmp.new or Android Studio's
Kotlin Multiplatform plugin). It's required by AGP 9, which moved the Android app out of the shared module.

```
pushups/
├── androidApp/              Android application module (entry point + Android-only features)
│   └── src/main/kotlin/…    MainActivity, Application, widgets, notifications, Health Connect,
│                            app shortcuts, backup rules, haptics/sensor implementations
├── shared/                  KMP library — everything that can be shared
│   └── src/
│       ├── commonMain/kotlin/…
│       │   ├── domain/      models, GoalEngine, pace/streak/bank logic — pure Kotlin, no Compose
│       │   ├── data/        Room KMP database, DAOs, repositories, DataStore preferences
│       │   ├── platform/    interfaces: Haptics, ReminderScheduler, HealthSync, FileExporter, Clock
│       │   └── ui/
│       │       ├── designsystem/   tokens, Aurora, GlassSurface, components, motion specs
│       │       ├── screens/        today, count, month, year, settings, onboarding
│       │       ├── navigation/
│       │       └── debug/          Gallery, direction switcher, data seeder (debug builds only)
│       ├── commonTest/      GoalEngine and repository tests
│       ├── androidMain/     Android implementations of platform interfaces
│       └── iosMain/         (later)
├── iosApp/                  Xcode project (generated now, built later)
├── docs/                    this pack
├── gradle/libs.versions.toml
└── CLAUDE.md
```

When generating: choose **Android + iOS** with **shared UI (Compose Multiplatform)**. Optionally add
**Desktop** for the hot-reload design sandbox (§10). Package/application id: `com.justinkirkey.pushups`
(changeable until the first Play Store upload; confirm with JK).

**Layering rule:** `domain` depends on nothing. `data` depends on `domain`. `ui` depends on both.
Nothing in `domain` or `data` imports Compose, so they can move to a `sharedLogic` module if iOS ever
goes SwiftUI.

## 4. Android configuration

- **minSdk 31** (Android 12): real blur via RenderEffect everywhere. Refraction shaders need API 33+;
  31–32 get blur-only glass. Revisit minSdk for the Play launch.
- **targetSdk / compileSdk:** latest stable.
- **Permissions:** `POST_NOTIFICATIONS` (requested when the user turns on reminders), `VIBRATE`,
  `RECEIVE_BOOT_COMPLETED` (re-schedule reminders). Health Connect permissions only when S2 is enabled.
  **No `INTERNET`.**
- **Edge-to-edge** layout, transparent system bars, predictive back enabled.
- **Auto Backup** on, with rules that include the Room database and DataStore files.
- **R8/minify** on for release; keep rules as needed.

## 5. Data model

```kotlin
// domain
data class RepEntry(
    val id: String,              // UUID
    val count: Int,              // 1..999
    val loggedAt: Instant,       // when the set happened
    val timeZone: String,        // zone id at logging time
    val localDate: LocalDate,    // derived from loggedAt + timeZone; the day it belongs to
    val source: EntrySource,     // MANUAL, QUICK_ADD, COUNT_MODE, WIDGET, NOTIFICATION, SHORTCUT, IMPORT
    val createdAt: Instant,
    val updatedAt: Instant,
)

data class GoalVersion(
    val id: String,
    val effectiveFrom: LocalDate,   // applies from this date until the next version
    val dailyTarget: Int,
    val monthlyGoalMode: MonthlyGoalMode,  // AUTO, CUSTOM
    val customMonthlyGoal: Int?,
    val restDays: Set<DayOfWeek>,
    val extraRepsMode: ExtraRepsMode,      // COUNT_TOWARD_MONTH (default), BANK_TOWARD_TOMORROW
)
```

Derived (computed, not stored): `DaySummary(date, total, target, scheduled, complete, bankIn, bankOut)`,
`MonthSummary(total, goal, expectedToDate, paceDelta, projection, completeDays, streak)`,
`YearSummary`, `PersonalBests`.

- Store entries; compute summaries in `GoalEngine` from entries + goal versions. Cache only if profiling
  shows a need (it won't at this data size: 10 years ≈ 20k rows).
- Index `RepEntry.localDate`.
- Deletes are hard deletes with an in-memory undo window (5 s).

## 6. GoalEngine

Pure functions, no I/O, exhaustively unit-tested. Inputs: entries, goal versions, a date range, "today".
Outputs: day/month/year summaries, pace, projection, streaks, bests. Implements PRD §5 exactly.
Every edge case in PRD §5.5 has a named test. Tests use fixed dates, never the real clock.

## 7. Platform features (androidApp)

| Feature | Approach |
| --- | --- |
| Haptics | `Vibrator` + `VibrationEffect.Composition` primitives; check `areAllPrimitivesSupported`, fall back to predefined effects (`EFFECT_CLICK`, `EFFECT_TICK`) |
| Reminders | `AlarmManager` inexact daily alarm (no exact-alarm permission) → receiver checks whether today is complete before notifying; re-schedule on boot and on settings change |
| Notification quick-log | Notification actions with `PendingIntent` → `BroadcastReceiver` → repository insert (source = NOTIFICATION) → update widgets |
| Widgets | Glance `GlanceAppWidget`; `ActionCallback` for tap-to-log; progress visual rendered to a bitmap; call `updateAll` after any data change |
| App shortcuts | Static shortcuts in XML: "Log N" (deep link), "Count mode" |
| Count mode | `FLAG_KEEP_SCREEN_ON` while open; whole-screen pointer input; debounce at ~250 ms to avoid double counts from a nose/chin tap |
| Export/import | Storage Access Framework (`CreateDocument` / `OpenDocument`), CSV |
| Tilt highlight (optional) | Accelerometer via `SensorManager`, low-pass filtered, only while the screen is visible |

All of these sit behind the `platform/` interfaces so iOS can provide its own versions later.

## 8. Health Connect (should-have)

- Write one `ExerciseSessionRecord` per entry: `exerciseType = EXERCISE_TYPE_CALISTHENICS`,
  `title = "Push-ups · 25 reps"`, start = `loggedAt − estimated duration (≈2 s per rep)`, end = `loggedAt`.
- Health Connect has **no push-up segment type** (checked Nov 2026: types include PLANK, SIT_UP,
  BURPEE, SQUAT, PULL_UP, but not push-up). Add one `ExerciseSegment` with `repetitions = count` using a
  type that's valid inside a calisthenics session — try `EXERCISE_SEGMENT_TYPE_OTHER_WORKOUT`, verify
  Health Connect accepts it, otherwise omit segments and rely on the title.
- Store the Health Connect record id on the entry so edits and deletes stay in sync.
- Off by default; turned on from Settings with the standard permission flow and a rationale screen.

## 9. Performance budget (Pixel 10, release build)

- Cold start to interactive Today: feels instant (target < 600 ms; measure later with Macrobenchmark).
- No dropped frames during logging animations, tab switches and Month/Year scrolling at 120 Hz (Pixel 10).
- Aurora + glass together cost < 4 ms per frame. Measure with the GPU profiler or `adb shell dumpsys gfxinfo`.
- Rules: don't blur large regions that are animating underneath every frame if it janks — cache, lower the
  blur radius, or limit glass to small floating controls. Avoid recomposing the whole screen on every rep
  (hoist state, use `derivedStateOf`, stable types).
- Baseline Profile and R8 before calling v1 done.

## 10. Design sandbox (optional, recommended for look-and-feel tinkering)

Add a **Desktop (JVM)** target used only for design iteration with **Compose Hot Reload**: edit a token,
see it change instantly in a desktop window on the Mac. CMP 1.12 also ships an experimental MCP server
for Hot Reload that lets Claude Code trigger reloads and take screenshots. Platform interfaces get no-op
desktop implementations. The phone remains the source of truth for performance, haptics and real glass.

## 11. Testing and verification

- `commonTest`: GoalEngine (all PRD §5.5 cases), repositories (in-memory Room), CSV round-trip.
- Migration tests for every schema change.
- UI: after each change, Claude Code installs on the emulator and takes screenshots for self-review.
- Before each phase sign-off: install the **release** build on JK's phone.

## 12. iOS later (not now, but don't block it)

- No `java.*`, `android.*` or JVM-only libraries in `commonMain`.
- Platform interfaces get `iosMain` implementations: Core Haptics, `UNUserNotificationCenter`, HealthKit,
  `UIDocumentPicker`.
- iOS widgets must be WidgetKit (Swift) reading a shared App Group store; plan the data layer so a
  small read-only summary can be exported for widgets on both platforms.
